# Primitive: transform(idea, operator)

**What:** Apply systematic operators to mutate an existing idea into variants.

**Why:** SCAMPER and TRIZ formalize transformation so you don't rely on random inspiration. Especially useful in persistence mode.

## SCAMPER Operators

| Operator | Question | Example |
|----------|----------|---------|
| **S**ubstitute | What component can be replaced? | Replace human review with AI triage |
| **C**ombine | What can be merged? | Combine onboarding with first value moment |
| **A**dapt | What can be borrowed from elsewhere? | Adapt game tutorial patterns to SaaS |
| **M**odify/Magnify | What can be made bigger, smaller, faster? | Make the feedback loop 10x faster |
| **P**ut to other use | Can this solve a different problem? | Use analytics dashboard as sales tool |
| **E**liminate | What can be removed? | Remove the signup form entirely |
| **R**everse/Rearrange | What if the order changed? | Let users use product first, sign up later |

## SCAMPER Protocol

1. State the base idea clearly
2. Apply each operator as a question
3. For each, generate 1-2 variants
4. Some will be obvious/useless — keep going
5. Mark surprising variants for further development

## TRIZ Contradiction Resolution

When an idea has a built-in contradiction ("we need X but X causes Y"):
1. State the contradiction explicitly
2. Apply separation principles:
   - **In time**: X happens at one time, not-X at another
   - **In space**: X in one place, not-X in another
   - **In condition**: X under condition A, not-X under condition B
   - **In scale**: X at system level, not-X at component level
3. Generate solutions that resolve the contradiction through separation
