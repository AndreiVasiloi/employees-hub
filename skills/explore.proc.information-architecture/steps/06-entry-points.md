# Step 6: Define Entry Points and Wayfinding

## Objective

Document how users navigate into and through the product — primary entry points, secondary paths, deep linking, and location awareness.

## Entry Criteria

- [ ] Step 5 (Labeling) complete with human validation

## Actions

### 6.1 Document Entry Points and Wayfinding

```
Entry Points and Wayfinding

**Primary entry points**:
- Home/landing page: [What users see first]
- Global navigation: [Always accessible sections]
- Search: [Scope and behavior]
- Primary CTAs: [Key actions]

**Secondary entry points**:
- Notifications: [How they link to content]
- Deep links: [From email/chat/shared links]
- Cross-links: [From related entities]

**Deep linking rules**:
- Deep links resolve to the most specific permitted view
- If no permission: [Show access message with recovery paths]
- If entity missing: [Show not found with search and support routes]

**Location awareness**:
- Page titles reflect current location and entity context
- Selected nav state matches current route
- Detail pages provide clear return path to list or parent

Does this wayfinding approach make sense?
```

**STOP**: Wait for human to validate wayfinding.

## Exit Criteria

- [ ] Primary and secondary entry points documented
- [ ] Deep linking rules defined with error states
- [ ] Location awareness rules documented
- [ ] Human has validated wayfinding approach
