# Step 3: Define Wireframe Conventions

## Objective

Establish consistent conventions for layout regions, component naming, annotation style, and fidelity rules.

## Entry Criteria

- [ ] Step 2 (Screen Inventory) complete with human validation

## Actions

### 3.1 Layout Regions

Define consistent regions across screens:
- Header (global nav, breadcrumbs, search, actions)
- Main (primary content area)
- Side (filters, contextual info, secondary actions — if applicable)
- Footer (optional)

### 3.2 Component Naming

Establish consistent terminology:
- List, Table, Card, Form, Modal, Drawer, Toast, Banner
- Any project-specific components

### 3.3 Annotation Style

- Numbered callouts for interactions
- State notes under each screen
- Open questions captured at end of each screen

### 3.4 Fidelity Rules

- Layout and hierarchy only, no visual styling
- Boxes, labels, and simple component names
- Placeholder copy where necessary
- Behavior and states in notes, not visuals

**STOP**: Wait for human to confirm conventions.

## Exit Criteria

- [ ] Layout regions defined
- [ ] Component naming established
- [ ] Annotation and fidelity rules documented
- [ ] Human has confirmed conventions
