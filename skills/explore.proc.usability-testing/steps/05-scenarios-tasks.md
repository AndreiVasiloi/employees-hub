# Step 5: Create Scenarios and Tasks

## Objective

Design realistic, unbiased tasks that test the key flows. Include at least one recovery task.

## Entry Criteria

- [ ] Step 4 (Participants) complete with human confirmation

## Actions

### 5.1 Task Structure Rules

- Use realistic scenarios, avoid leading wording
- One task per flow outcome
- Include at least one recovery task (error, change mind, permission limit)
- Start tasks with context, not instructions

### 5.2 Define Scenario

Short scenario that frames the user's goal and context.

### 5.3 Create Tasks (3-5)

For each task:
- Goal (what participant is trying to achieve)
- Starting point (where they begin)
- Task prompt (exact wording — realistic, non-leading)
- Success criteria (observable outcome)
- Data to capture (time, errors, confidence, path)
- Expected confusion points (where we anticipate issues)

### 5.4 Include Recovery Task

At least one task where participant must recover from an error, change their mind, or hit a permission limit.

**STOP**: Wait for human to validate tasks.

## Exit Criteria

- [ ] 3-5 tasks created with success criteria
- [ ] At least one recovery task included
- [ ] No leading language in task prompts
- [ ] Human has validated tasks
