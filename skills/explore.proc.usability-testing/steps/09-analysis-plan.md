# Step 9: Define Analysis Plan

## Objective

Specify how findings will be synthesized, severity rated, and delivered.

## Entry Criteria

- [ ] Step 8 (Logistics) complete with human confirmation

## Actions

### 9.1 Synthesis Approach

- Per-task summary (success rates, failure points, time, confidence)
- Cluster issues into themes (navigation, comprehension, interaction, content)
- Map issues to screens and flows
- Identify root causes (labeling, hierarchy, interaction, content)

### 9.2 Severity Rating

- **Critical**: Blocks task completion or causes harmful error → Must fix before launch
- **High**: Major friction or repeated confusion → Should fix before launch
- **Medium**: Slows progress, workaround exists → Fix in next iteration
- **Low**: Cosmetic or minor annoyance → Nice to have, backlog

### 9.3 Output Deliverables

- Findings report: `usability-findings-[slug].md`
- Recommendations: Prioritized changes with rationale
- Updated wireframes or prototype (if quick wins)
- Timeline for deliverables

**STOP**: Wait for human to confirm analysis plan.

## Exit Criteria

- [ ] Synthesis approach defined
- [ ] Severity rating levels documented
- [ ] Output deliverables listed with timeline
- [ ] Human has confirmed analysis plan
