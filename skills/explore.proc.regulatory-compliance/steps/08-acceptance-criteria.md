# Step 8: Generate Compliance Acceptance Criteria

## Objective

Create testable acceptance criteria for QA validation and definition of done, organized by compliance area.

## Entry Criteria

- [ ] Step 7 (Non-Negotiables) complete

## Actions

### 8.1 Generate Criteria by Area

Create checkbox-style acceptance criteria for:

- **Data Collection and Consent** (privacy policy, consent mechanisms, age gates)
- **Data Retention and Deletion** (automatic deletion, user requests, logging)
- **Data Security** (encryption, access controls, MFA, breach detection)
- **Accessibility** (keyboard, screen reader, contrast, alt text, labels)
- **Disclosures** (ToS, privacy policy, cookie notice, breach notification)
- **Audit and Evidence** (logging, retention, searchability, DPAs)
- **Regional Compliance** (region-specific criteria)

### 8.2 Map to PRD and QA

Note that these criteria should be added to:
- PRD functional requirements
- QA test plans
- Definition of done

## Exit Criteria

- [ ] Acceptance criteria generated for all compliance areas
- [ ] All criteria are testable (pass/fail)
- [ ] Criteria ready for PRD and QA integration
