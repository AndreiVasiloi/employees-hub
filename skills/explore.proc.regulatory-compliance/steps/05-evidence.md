# Step 5: Define Evidence Requirements

## Objective

Document what must be logged and proven for compliance — audit logs, confirmations, proof of compliance, and retention/retrieval rules.

## Entry Criteria

- [ ] Step 4 (Disclosures) complete

## Actions

### 5.1 Audit Logs

Define what must be logged:
- User actions (login, consent, access, modifications, deletions)
- System actions (automated decisions, transfers, security events, config changes)
- Administrative actions (role changes, permission changes, system config)

### 5.2 Log Requirements

- Retention period
- Storage (secure, encrypted, immutable)
- Format (structured, searchable)
- Access controls (who can access logs, logging access to logs)

### 5.3 Confirmations and Records

- Consent records (timestamp, user ID, type, version, method)
- Transaction records
- Communication records
- Audit trail (complete change history)

### 5.4 Proof of Compliance

- Security certifications and renewal schedule
- Penetration test reports and frequency
- Accessibility test reports and frequency
- Privacy impact assessments
- Data processing agreements

### 5.5 Retention and Retrieval

- Legal hold process
- Minimum and maximum retention by record type
- Response time requirements (user requests, regulatory, legal)
- Export format and redaction rules

## Exit Criteria

- [ ] Audit log requirements documented
- [ ] Log retention and access rules defined
- [ ] Record types and content specified
- [ ] Proof of compliance requirements listed
- [ ] Retention and retrieval rules documented
