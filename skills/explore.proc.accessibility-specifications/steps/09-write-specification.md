# Step 9: Write Accessibility Specifications Document

## Objective

Write the complete accessibility specification document to `explore/design/accessibility-[slug].md` consolidating all findings from Steps 1-8.

## Entry Criteria

- [ ] Steps 1-8 complete with all requirements confirmed
- [ ] Baseline, flows, cross-cutting requirements, component specs, state specs, flow checks, acceptance criteria, and risks all documented

## Actions

### 9.1 Write Complete Specification

Write complete accessibility spec to `explore/design/accessibility-[slug].md` with all sections.

**Use template**: `templates/accessibility-template.md`

**Required sections**:
1. **Snapshot** — Objective, Scope, References
2. **Conformance Target and Test Baseline** — Standard, platforms, assistive tech (from Step 1)
3. **Cross-Cutting Requirements** — Structure, Keyboard, Forms, Visual, Content (from Step 3)
4. **Component Specifications** — Per component type with keyboard, focus, semantics, announcements (from Step 4)
5. **State Specifications** — Empty, Loading, Error, No permission, Success (from Step 5)
6. **Flow-Level Accessibility Checks** — Per P0 flow checklists (from Step 6)
7. **Acceptance Criteria** — Definition of done, testing approach (from Step 7)
8. **Open Questions and Risks** — Questions, risks, known limitations (from Step 8)

### 9.2 Consolidation Quality Check

Verify that:
- All content from Steps 1-8 is included in the specification
- Template structure is followed completely
- All sections are populated with specific, testable requirements
- No placeholder text remains
- Links and references are correct

## Exit Criteria

- [ ] Specification document written to `explore/design/accessibility-[slug].md`
- [ ] All 8 required sections populated
- [ ] Template structure followed
- [ ] All findings from Steps 1-8 consolidated
