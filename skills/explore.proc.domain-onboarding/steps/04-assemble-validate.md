# Step 4: Assemble and Validate Domain Profile

Compile all interview responses into a structured domain profile using the template.

Write the domain profile to `persistent-knowledge/[domain]-profile.md`.

**Validation checklist** (re-run after any profile modification):

- [ ] Domain vocabulary captured with definitions (not just term names)
- [ ] Ambiguous terms identified with context-specific meanings
- [ ] Core business process or workflow described
- [ ] Bounded contexts or sub-domains identified
- [ ] Regulatory landscape documented (or explicitly marked "none applicable")
- [ ] Technical, organizational, and timeline constraints captured
- [ ] Common architectural patterns listed with when-to-use and when-not-to-use
- [ ] Authority patterns documented for truth hierarchy guidance
- [ ] Quality attribute priorities ranked
- [ ] Domain-specific hardening items identified (if any)

```
Domain Profile Complete

File: persistent-knowledge/[domain]-profile.md
Domain: [Name]
Vocabulary terms: [N]
Regulations: [N] (or "none applicable")
Constraints: [N] technical, [N] organizational, [N] regulatory
Patterns: [N] documented
Authority types: [N] identified
Quality priorities: [top 3-5 listed]
Domain hardening items: [N]
Validation: [N] of 10 checks passed ✓

This profile is now available as persistent knowledge for all future
engagements in the [domain] domain.
```

**STOP**: Wait for human to review and approve the domain profile (STOP DO-1).
